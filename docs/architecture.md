# AmiFlow — Architecture

AmiFlow — это Web site + backend‑платформа, которая автоматизирует выкладку объявлений на Авито:  
создание, обновление, уникализацию и Smart‑Migration, строго через официальные API Авито.

---

## 1. High‑level обзор

### Компоненты системы

- **Web site (Frontend)**  
  Красивый лендинг для привлечения внимания.

  Авторизация через Авито.

  Интерфейс для пользователя:
  создание шаблонов, вариантов, запуск публикаций, просмотр статусов.

- **Backend API (FastAPI)**  
  Основная бизнес‑логика, работа с БД, очередями, интеграциями с Авито и AI.

- **Workers**  
  Асинхронные фоновые задачи: публикация, обновление, миграция, анализ и исправление отклонений.

- **Avito Integrations**  
  Официальные API Авито:
  - OAuth (Авторизация)
  - Autoload API (Автозагрузка)
  - (опционально) Listings API для точечных обновлений

- **AI / RAG слой**  
  Уникализация текстов, генерация описаний, помощь в анализе отклонений.

- **Billing & Slots**  
  Учёт слотов (подключённых аккаунтов Авито) и использование AI.

- **Notifications**  
  Уведомления о проблемах и статусах (ошибки публикации, отклонения, авторизация, биллинг).

## 2. Пользовательский поток (как работает сервис)

### 2.1 Привязка аккаунта Авито (OAuth)

1. Пользователь в VK Mini App нажимает кнопку **«Привязать аккаунт Авито»**.  
2. VK Mini App открывает OAuth‑страницу Авито.  
3. Пользователь даёт разрешение AmiFlow.  
4. Авито возвращает `code` → backend получает `access_token` + `refresh_token`.  
5. Backend сохраняет токены и связывает их с **Slot** (слот = 1 аккаунт Авито).

**Зачем:**  
Без этого AmiFlow не может публиковать объявления от имени пользователя.

---

### 2.2 Создание разных обьявлений внутри одного шаблона.

1. В шаблоне пользователь выбирает аккаунт(ы) для публикаций, Города (гео). 
2.. Пользователь нажимает «Создать обьявление» внутри шаблона. 
3. Его перекидывает на сайт Авито (в браузере), где он вручную заполняет форму объявления.  
4. AmiFlow (через Playwright Recording / аналогичный механизм) **считывает структуру формы**:
   - какие поля есть
   - какие атрибуты
   - какие значения
   - какие категории
   - файлы (фото)
5. Эта структура сохраняется в `recording_meta` у Template/Variant.

**Важно:**  
AmiFlow **не автоматизирует действия пользователя**, а только **запоминает структуру формы**, чтобы потом правильно формировать фид.

Важное уточнение: Но при добавлении больше 1 обьявления, тоесть при повторном создании обьявления уже с другими параметрами *которые настраивает пользователь*, AI обязан автоматически заполнять поля названия и описания уже уникализированные.

---

### 2.3 Конвертация в фид (Autoload feed)

На основе:

- `Template`
- `Variant`
- `recording_meta`

Backend формирует **фид** (XML/JSON) в формате, который ожидает **Avito Autoload API**.

**Зачем:**  
Autoload работает с фидами, а не с формами. AmiFlow превращает заполненную форму в корректный фид.

---

### 2.4 Запуск AI‑агента выкладки

Когда пользователь «запускает AI‑агента» в AmiFlow, это означает:

- включить автоматическую публикацию фидов через Autoload API  
- включить AI‑unique (уникализацию текстов, униклизацию фото)  
- включить авто‑обновление (AI автоматически подбирает лучшее время для обновления)

---

### 2.5 Публикация через Autoload API

1. Backend создаёт **PostingTask** для каждого Variants/фида.  
2. **posting_worker** берёт задачу из очереди.  
3. Формирует фид (если ещё не сформирован).  
4. Отправляет фид в **Avito Autoload API**.  
5. Периодически опрашивает статус (success / error / rejected).  
6. Обновляет статус Variant / PostingTask.  
7. В случае ошибок — создаёт **RejectionCase**.

---

### 2.6 Обновление объявлений

Для обновления:

- цены  
- описания  
- фото

AmiFlow:

1. Создаёт **UpdateTask**.  
2. **update_worker** отправляет обновление через:
   - либо новый фид (Autoload)
   - либо (опционально) Listings API, если это оправдано.

---

### 2.7 Smart‑Migration

Smart‑Migration = массовое копирование объявлений 1:1.

1. Алгоритм автомтически определяет лучшие обьявления по показателям (Вовлечение) и копирует их на другие аккаунты.
2. Создаёт новые Variants, **строго 1:1**.  
3. Формирует фид.  
4. Публикует через Autoload API.

---

### 2.8 AI‑unique (уникализация)

Для Variants типа `ai_unique`:

1. Берётся исходный текст (title/description).  
2. Через RAG + LLM генерируется **лёгкая переформулировка**.  
3. Структура объявления (параметры, категория) **не меняется**.  
4. Новый текст сохраняется в Variant.  
5. Дальше — обычная публикация через Autoload.

## Viktor API (уникализация фото)

AmiFlow интегрируется с **Viktor API** — сервисом уникализации изображений.

**Назначение:**
- генерация «уникальной» версии фото, для создания большого количества обьявлений.

**Как используется в AmiFlow:**
- backend отправляет исходные изображения в Viktor API
- получает уникализированные версии и подставляет их в Variant перед формированием фида
- оригиналы могут храниться отдельно для аудита

### 2.9 Rejection Analyzer & Solver

Если Авито отклоняет объявление:

1. Создаётся **RejectionCase** с причиной.  
2. **Rejection Analyzer**:
   - классифицирует причину  
   - определяет, можно ли исправить автоматически  

3. **Rejection Solver**:
   - предлагает изменения (например, убрать запрещённые слова)  
   - применяет их к Variant (если включён auto‑fix)  
   - создаёт новый PostingTask для повторной публикации
